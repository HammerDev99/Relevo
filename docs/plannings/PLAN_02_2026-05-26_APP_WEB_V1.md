## 1. Stack confirmado y justificación

| Capa | Tecnología | Razón |
|------|-----------|-------|
| Framework web | **FastAPI** | Tipado moderno (compatible con mypy strict), async, docs OpenAPI automáticas, rápido |
| Templates | **Jinja2** | Integrado en FastAPI, renders HTML server-side |
| Interactividad | **HTMX** | Añade actualizaciones parciales de página sin escribir JavaScript; una petición HTTP por acción |
| BD | **SQLite** | Cero configuración, suficiente para 10 usuarios; portable a PostgreSQL cambiando solo la connection string |
| ORM | **SQLAlchemy 2.x** | API moderna con tipado, context managers, soporta SQLite → PostgreSQL sin cambios en modelos |
| Auth | **Sesiones firmadas** (`itsdangerous`) | Más natural en web clásica que JWT; cookies `HttpOnly` + `SameSite=Strict` |
| Cálculo festivos | **`src/relevo/`** | Módulo ya construido y verificado (SPRINT_01); no se duplica lógica |
| Despliegue | **Dockerfile + EasyPanel** | EasyPanel gestiona el container, SSL (Let's Encrypt) y el dominio de la Rama Judicial |

### Decisiones diferidas a la v2

- **PostgreSQL**: migración trivial (connection string + `pip install psycopg2-binary`); hacerla cuando el volumen lo justifique o cuando EasyPanel permita crear el servicio de BD fácilmente.
- **SSO/LDAP institucional**: si el dominio de la Rama Judicial expone un directorio LDAP/AD, la v2 puede reemplazar la tabla `empleados` con autenticación delegada.

## 4. Lógica de dominio (domain.py)

### 4.1 Validar saldo (RN2)

```
vacaciones_aprobadas(empleado, anio) = sum(dias_habiles de solicitudes aprobadas
                                          WHERE tipo='vacaciones' AND anio(fecha)=anio
                                          AND empleado_id=empleado.id)

si vacaciones_aprobadas + nueva.dias_habiles > 22 → Failure("Saldo vacaciones insuficiente")

permiso_usado(empleado, anio, mes) = sum(dias_habiles de solicitudes aprobadas
                                        WHERE tipo='permiso' AND anio/mes=anio/mes
                                        AND empleado_id=empleado.id)

si permiso_usado + nueva.dias_habiles > 3 → Failure("Saldo permiso insuficiente para el mes")
```

### 4.2 Validar concurrencia (RN3/RN4)

Para cada día en el rango `[fecha_inicio, fecha_fin]`:

```
ausentes_ese_dia = count(solicitudes aprobadas WHERE fecha_inicio <= dia AND fecha_fin >= dia)

modo_estandar:
  si ausentes_ese_dia >= 1 → Failure("Cupo lleno para {dia}")

modo_excepcion (nueva.es_excepcion=True):
  si ausentes_ese_dia >= 2 → Failure("Cupo máximo de excepción para {dia}")
  validar que la combinación sea legal (RN4):
    - al menos una de las ausentes es vacaciones y la nueva es permiso, O
    - ambas son permisos con justificación
  si no cumple → Failure("Excepción no válida: requiere (vacaciones+permiso) o (2 permisos justificados)")
```

### 4.3 Validar respaldo (RN6)

```
si nueva.respaldo_id es None → Failure("Debes indicar un compañero de respaldo")
si nueva.respaldo_id == nueva.empleado_id → Failure("No puedes ser tu propio respaldo")
si respaldo.activo == False → Failure("El compañero de respaldo no está activo")
```

## 5. Endpoints y vistas

| Método | Ruta | Rol | Descripción |
|--------|------|-----|-------------|
| GET | `/` | cualquiera | Redirect → `/solicitudes` (si auth) o `/login` |
| GET | `/login` | anónimo | Formulario de login |
| POST | `/login` | anónimo | Autenticar; setear cookie de sesión |
| GET | `/logout` | auth | Limpiar sesión |
| GET | `/solicitudes` | empleado | Mis solicitudes + estado de cada una |
| GET | `/solicitudes/nueva` | empleado | Formulario de solicitud (muestra disponibilidad) |
| POST | `/solicitudes/nueva` | empleado | Crear solicitud (valida dominio) |
| GET | `/disponibilidad` | empleado | Vista de calendario — solo estados, **sin PII** (RN5) |
| GET | `/coordinacion` | coordinacion | Panel con todas las solicitudes pendientes |
| GET | `/coordinacion/solicitudes/{id}` | coordinacion | Detalle con PII + historial |
| POST | `/coordinacion/solicitudes/{id}/aprobar` | coordinacion | Aprobar (con validación) |
| POST | `/coordinacion/solicitudes/{id}/rechazar` | coordinacion | Rechazar con motivo |

### Vista de disponibilidad (RN5)

La respuesta de `/disponibilidad` calcula para cada día del mes:
- `DISPONIBLE` → 0 solicitudes aprobadas ese día
- `OCUPADO (1/1)` → 1 solicitud aprobada
- `EXCEPCIONAL (2/2)` → 2 solicitudes aprobadas (excepción)

**No expone**: nombre del empleado, tipo de ausencia, motivo, ni ID. Solo la fecha y el estado derivado.

## 6. Auth: sesiones firmadas

- Al login exitoso: crear `session_token` = HMAC firmado con `SECRET_KEY` que contiene `{empleado_id, rol, expiry}`.
- Almacenar en cookie `HttpOnly`, `SameSite=Strict`, `Secure` (HTTPS vía EasyPanel/Let's Encrypt).
- Dependencia FastAPI `get_empleado_actual(request)`: decodifica la cookie, valida firma y expiración; retorna `Empleado` o lanza 401.
- Dependencia `get_coordinador(empleado=Depends(get_empleado_actual))`: verifica `empleado.rol == "coordinacion"` o lanza 403.

## 7. Despliegue: Dockerfile + EasyPanel

### Dockerfile

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY pyproject.toml requirements*.txt ./
RUN pip install --no-cache-dir -e .
COPY src/ ./src/
COPY src/app/templates/ ./src/app/templates/
COPY src/app/static/ ./src/app/static/
EXPOSE 8000
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

### Flujo EasyPanel

1. Subir código a un repositorio (GitHub/GitLab o repositorio propio).
2. En EasyPanel → Nuevo Proyecto → elegir repo → EasyPanel detecta Dockerfile.
3. Configurar variables de entorno: `SECRET_KEY`, `DATABASE_URL` (SQLite en volumen persistente), `ADMIN_EMAIL`.
4. EasyPanel asigna el dominio autorizado de la Rama Judicial + provee SSL automático.
5. El volumen de SQLite se mapea a `/data/relevo.db` (persistente entre reinicios).

### docker-compose.yml (desarrollo local)

```yaml
services:
  app:
    build: .
    ports:
      - "8000:8000"
    volumes:
      - ./data:/data
      - ./src:/app/src
    environment:
      - SECRET_KEY=dev-secret-key-cambiar-en-produccion
      - DATABASE_URL=sqlite:////data/relevo.db
```

## 11. Riesgos

| Riesgo | Impacto | Mitigación |
|--------|---------|------------|
| **Habeas Data (Ley 1581/2012)**: la app maneja PII (nombres, motivos de permiso) de empleados | Alto | PII restringida a coordinación (RN5); BD en VPS propio de la Rama (no terceros); no logs con PII |
| **SECRET_KEY expuesta**: si se hardcodea, las sesiones son falsificables | Crítico | Variable de entorno `SECRET_KEY` en EasyPanel; nunca en el código |
| **Pérdida de datos SQLite**: el volumen Docker no está en backup automático | Medio | EasyPanel permite snapshot de volúmenes; documentar proceso de backup manual; SQLite es un solo archivo |
| **Concurrencia en race condition**: dos solicitudes simultáneas para la misma fecha | Bajo | SQLAlchemy con transacciones + `SELECT FOR UPDATE` al validar; aceptable para 10 usuarios |
| **EasyPanel sin soporte institucional**: si la Rama Judicial no aprueba el panel | Bajo | EasyPanel solo gestiona containers Docker; el despliegue alternativo es nginx + systemd directo |
